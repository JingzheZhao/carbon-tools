## 零、总结论

infrared.city 最强的不是三维,是**把一个数字解释清楚**的那套结构。这恰好是我们最该补的一课。

三个可直接移植的东西:

1. **结果面板的七段式阶梯**(最有价值)
2. **画布即应用**的布局骨架
3. **场景为一等公民 + 密度渐进**的对比机制

# 第一部分:结果面板 —— 七段式阶梯

点开任何一个分析结果,顺序永远是这七段,一段不少。这是最该原样照抄的结构。

## 一、七段的定义

| 段 | 内容 | infrared 实例 | 我们的对应 |
|---|---|---|---|
| ① **元数据** | 范围·面积·数量·生成时间 | `Site · 0.343 km² · 5 tiles · Generated 28 Aug, 22:15` | `广场 · 1000㎡ · 27 构件 · 同步于 14:02` |
| ② **一句话定义** | 这个指标是什么,给谁看 | "体感温度,综合气温、风、湿度与辐射 —— 行人热应激风险的标准指标" | "隐含碳:材料生产、运输、施工产生的一次性排放" |
| ③ **FINDINGS 叙述** | 带数字的白话结论 | "均值 21.3°C,峰值 24.0°C。100% 面积位于舒适区(9–26°C,无热应激);0% 处于强热应激(>32°C,对易感人群在长时间暴露下构成健康风险)" | 见 §二 写法 |
| ④ **KPI 方块** | 2×2,四个数 | 均值 / 峰值 / 舒适区占比 / 热应激占比 | 隐含碳 / 固碳 / 净值 / 碳中和年 |
| ⑤ **分布图** | 带色带,标 min/μ/max | 直方图 | 按构件类别的堆叠条 |
| ⑥ **背景对照** | 跟基准比 | "EPW 夏季高温 33.2°C…UTCI 高于环境高温说明存在城市热放大" | 跟行业基准 / 2030 目标比 |
| ⑦ **METHODOLOGY + ASSUMPTIONS** | 方法 + 假设清单(折叠) | 见 §三 | 见 §三 |

## 二、③ FINDINGS 的写法

infrared 的叙述有两个值得学的动作:

1. **点出阈值**,不只报数字 —— "0% 处于强热应激(**>32°C**)"
2. **点出受影响的人** —— "对**易感人群**在**长时间暴露**下构成健康风险"

我们的碳报告照这个写法:

> ❌ "隐含碳 221 吨,固碳 −18 吨,净 203 吨。"
>
> ✅ "这个方案排放 221 吨,场地植被 60 年只能固回 18 吨。**净 203 吨,相当于这块广场三十年固碳量的十一倍被一次性花掉。**当前处于 ASLA 2030 目标线之上 42%,把 30 米挡墙改成缓坡可以拉回目标线内。"

规则:**数字 + 阈值 + 谁受影响 + 下一步能做什么**。

## 三、⑦ ASSUMPTIONS —— 最该抄的一段

infrared 的假设是这么写的:

```
▾ ASSUMPTIONS
  · Weather: EPW from Bishop-Toronto.City.AP, CAN
    (0.0 km from site, fetched 2026-08-29)
  · Ground material emissivity per the layer
    (asphalt, concrete, soil, vegetation, water)
  · Stress thresholds per ISO 7730 UTCI categories
```

注意它交代了:

- **气象站离场地多远**(0.0 km)
- **数据什么时候取的**(fetched 2026-08-29)
- **阈值出自哪个标准**(ISO 7730)

**这就是我们那套「来路」机制的成品形态** —— 而且它证明了这个做法在真实产品里站得住,不是拍脑袋。

我们的对应写法:

```
▾ 假设清单(7 项)
  · 灯具密度 0.5%/㎡ —— CC 默认值,未在模型中找到灯具
    〔在 Rhino 里画出灯具可替换此项〕
  · 配筋率 —— CC 配方 033001.21,95% 覆盖率
  · 碳因子来源 —— Carbon Conscience V2 数据集(2023),
    低/中/高三档;引用数 >5 时中位为真中位数
  · 固碳曲线 —— 逻辑斯蒂,成熟年份 80 年(木本),投影至第 60 年
```

**每一条假设后面都跟一句"怎么把它变成实测"**,这是我们比 infrared 更进一步的地方。

## 四、来路标记的视觉语言

沿用制图惯例 —— 实线 = 实测,虚线 = 假设:

| 来路 | 标记 | 颜色 |
|---|---|---|
| 实测 MEASURED | 实线下划线 / 实心 chip | 主色(蓝) |
| 推定 INFERRED | 点线 / 描边 chip | 主色(蓝) |
| 假设 ASSUMED | 虚线 / 浅底 chip | 次色(赭) |

**每个数字旁边都带标记**,点开能看到"这 12 吨来自你画的 30 米挡墙"。

# 第二部分:布局骨架

## 五、画布即应用

```
┌─ 顶栏:logo · 模式切换 · 项目状态 · 头像 ─────────────────────┐
├─┬────────────┬──────────────────────────────┬─────────────┬─┤
│ │ 左面板      │                              │ 右卡片       │ │
│左│ ┌──────────┐│                              │ 项目名       │右│
│图│ │材料 / 结果③││        画布铺满整屏           │ 1000㎡      │图│
│标│ └──────────┘│      (three.js 三维)         │ 场景 chips  │标│
│栏│ 搜索框       │                              │ + 新增       │栏│
│ │ 分类列表     │      面板浮在画布之上           │ 图层 | 对比  │ │
└─┴────────────┴──────────────────────────────┴─────────────┴─┘
```

四条规则:

1. **画布铺满,面板浮在上面。**
   CC 是死板的左右对半分,永远只能看半个图。我们做三维的更该学 infrared 这种浮层做法。

2. **左面板用 Tab 把「输入」和「输出」叠在一起,不是两个页面。**
   `材料` / `结果 ③`(带数量角标)。用户不用在页面间跳。

3. **两条图标栏各司其职。**
   - 最左 = 应用分区(项目 / 材料 / 历史 / 设置)
   - 最右 = 视口工具(相机、指北针、量尺、文字、太阳角度、图钉、剖切)
   - "我在干什么" 和 "我怎么看" 分开。

4. **右卡片是状态,不是内容。**
   项目名 + 面积 + 场景 chip + 三个动作。极小,但始终在。

## 六、颜色的贯穿

决策记录 §十三 已定:颜色 = 材料族。这套色必须贯穿:

```
Rhino 视口 → 网页三维 → 图例 → 饼图/柱状图 → 报告
```

视觉语言由用户自己定义,我们不需要另外设计配色。这是相对 infrared 的优势 —— 它的配色是固定的热力图色带,用户无法参与。

# 第三部分:交互机制

## 七、场景是一等公民

infrared 的做法:`Baseline •` chip + `+ Add` + `Compare`。

对比视图里 **列 = 场景,行 = 指标**。加一个方案就多一列。

```
                    Baseline        方案 A         方案 B
                    OSM baseline    透水铺装        保留乔木
  ─────────────────────────────────────────────────────────
  隐含碳             221 t          198 t          176 t
  固碳               −18 t          −18 t          −64 t
  净值               203 t          180 t          112 t
  碳中和年           —              —              第 47 年
```

这正是决策记录 §七 要的 A/B 对比。

## 八、Total / Δ / % 三态切换

同一份数据三种说法,一个按钮切换:

| 模式 | 显示 | 用途 |
|---|---|---|
| **Total** | 203 t | 绝对量,对工程师 |
| **Δ** | −23 t | 比基准少多少,对设计决策 |
| **%** | −11% | 百分比,对甲方汇报 |

极便宜,极有用。**必做。**

## 九、密度渐进

infrared 用一个工具条把同一份内容切成五档密度:

```
大卡片 → 小卡片 → 条 → 隐藏 → 纯表格
```

**表格档就是可以直接进报告的形态**。这解决了"演示看图 / 交付看表"的矛盾,不用做两套界面。

## 十、空状态会教下一步

infrared:

> "1 scenario · 2 workflows — you're looking at your baseline; **add a scenario in Setup to compare**"

我们的:

> "只有 1 个方案 —— 你正在看基准。在 Rhino 里换一版材料再同步一次,就能对比。"

**空状态不是"暂无数据",是下一步操作说明。**

## 十一、先入购物车,再结账(仅思路)

infrared 的分析要花 token,单价写在卡片上(`200 tokens`)并解释("Pricing scales with your project area"),点 Details 看清楚再 `Add to cart`。**决策和花钱分离。**

我们的工具免费开源,**整套计量 UI 直接删**。但"承诺前先看清代价"的思路保留 —— 长时间计算(如 60 年逐年固碳投影、大模型同步)前给出预估。

# 第四部分:目录卡片 —— 一个重要的区分

## 十二、infrared 的 workflow 卡片

```
┌────────────────────────────────────────┐
│ 🔥 Heat Island — Extreme Conditions    │  ← 5 ANALYSES
│    压力测试你的场地在极端高温下的表现,      │
│    找出热风险聚集处                       │
│    [Engineering] [Stakeholder]          │  ← 受众标签
│    200 tokens  ✓ Validated   Details → │  ← 价格 + 可信度徽章
└────────────────────────────────────────┘

展开后:
  ABOUT       两段 —— 做什么 + 什么时候用
  方法论博客 ↗
  ✓ Validated against heatwave-period climate records
  USE CASES   四条,写成"待办任务"的语气:
              · 区域最坏情况韧性筛查
              · 气候适应极端情景规划
              · 论证应急降温投资
              · 易感人群热风险制图
```

## 十三、关键区分:目录用在哪根轴上

**目录式入口本身没错,错在用错了轴。**

| 用在 | 结果 |
|---|---|
| ❌ **材料** | 就成了 CC 的 193 个复合场景,用户不知道选哪个 |
| ✅ **问题** | "这个方案能不能达到 2030 目标?" "保留这排树值不值?" 一个 workflow 打包若干分析 |

系统设计里取消的是**材料轴上的 20 个场景入口**;**问题轴上的 workflow 目录应该做**。

我们的候选 workflow:

- **达标筛查** —— 对照 ASLA 2030 / ILFI Zero Carbon / Atelier Ten 185 基准
- **保留 vs 拆除** —— 现状植被的双曲线对比
- **材料替换扫描** —— 在所有「假设」槽位上搜索低碳替代
- **碳中和年推演** —— 什么条件下曲线穿过零线

## 十四、两个可借的细节

1. **受众标签**(Engineering / Stakeholder)—— 告诉用户这份输出该用哪种语气,也帮我们决定报告模板。
2. **Validated 徽章 + 验证依据** —— 我们做开源工具,"依据 Carbon Conscience V2 数据集 / 已与 CC 逐位对齐"就是我们的徽章。系统设计 §五 那张 10 米 = 173.9 完全吻合的验证表,就是徽章后面的证据。

# 第五部分:不要学的三件事

## 十五、token 计费

用户的工具免费开源,整套计量 UI 删掉。见 §十一。

## 十六、只能推拉体块的几何编辑

infrared 的编辑模式只有 **移动 / 旋转 / 删除** 建筑体块:

```
Edit Buildings
  Move    ↑↓
  Rotate  Alt + ↑↓
  Delete  ⌫
```

(见 `references/04-edit-buildings-shortcuts.png`)

**这正是它的天花板,也正是我们的起点。**我们的几何来自 Rhino,精度和自由度完全不是一个量级。这条差异要在产品叙事里守住。

## 十七、黑盒的组合

infrared 的 "5 analyses" 是黑盒 —— 用户看不到这 5 个分析怎么组合的、各占多少权重。

**我们的来路机制正好相反,是透明的。**这个差异是我们的核心资产,不要为了界面简洁牺牲它。折叠可以,隐藏不行。
