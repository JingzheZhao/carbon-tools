## 一、环境与项目搭建

**发现的本机环境**：
- Rhino 8（`8.30.26103.11001`），实际安装在 `D:\Softwares\Rhino`（非默认 `C:\Program Files` 路径）
- SDK 依赖定位：
  - `RhinoCommon.dll` → `D:\Softwares\Rhino\System\`
  - `Grasshopper.dll` / `GH_IO.dll` → `D:\Softwares\Rhino\Plug-ins\Grasshopper\`
  - `Newtonsoft.Json.dll`（13.0.3）→ `D:\Softwares\Rhino\System\`，Rhino 自带，可直接引用不用另装包
- `dotnet` SDK 9.0.304 可用

**新建项目**：`E:\Carbon\gh-plugin\CarbonTools\`
- `CarbonTools.csproj`：`net48` 类库，`<TargetExt>.gha</TargetExt>` 让编译产物直接是 `.gha`
- 引用上述三个 DLL，`<Private>False</Private>`（Rhino 运行时自带这些程序集，不需要插件打包携带）
- 编译后自动把 `.gha` 拷贝到 `%APPDATA%\Grasshopper\Libraries\`（MSBuild `AfterTargets="Build"` 任务），每次 `dotnet build` 完就能在 GH 里直接测

## 二、CC Group 电池

文件：[Components/CCGroupComponent.cs](gh-plugin/CarbonTools/Components/CCGroupComponent.cs)、[Components/CCGroupComponentAttributes.cs](gh-plugin/CarbonTools/Components/CCGroupComponentAttributes.cs)

### 2.1 基本形态
- 输入：`Geometry`（list，接受任意几何）
- 输出：`Tagged Objects`（list）
- **没有独立的 Color 输入口** —— 颜色完全通过电池本体上的色块选择，不作为可连线的参数存在（讨论过程中明确否决了"Color 作为普通输入参数"的方案，因为色块已经能选颜色，多一个输入口是重复）

### 2.2 颜色选择交互（迭代了三版）
1. **第一版**：用 `pManager.AddColourParameter` 挂一个 GH 原生 `Param_Colour`，选色靠右键"Set Colour…"——能用，但用户发现"不知道能点"、"要右键才行，不直观"
2. **第二版**：自定义 `CCGroupComponentAttributes : GH_ComponentAttributes`，在电池本体下方画一条常驻色块，**单击**（不用右键）直接调用 `Rhino.UI.Dialogs.ShowColorDialog`（就是 Rhino 原生那个色轮+RGBA面板，右键菜单调的也是它），色块本身实时显示当前选中颜色，文字颜色按背景亮度自动切黑/白保证可读
3. **第三版**：去掉 Color 输入口本身（见 2.1），颜色变成组件的持久化状态：
   - `CurrentColor` 属性存在组件实例上
   - 重写 `Write` / `Read`（`GH_IO.Serialization.GH_IWriter/IReader`，用 `SetDrawingColor`/`GetDrawingColor`）把颜色写进 `.gh` 文件，保证存盘重开不丢颜色

### 2.3 图标
- 一开始 `Icon => null`，GH 会自动补一个"缺失图标"棋盘格占位图，用户反馈这个和色块重复、多余
- 改为用 `System.Drawing.Graphics` 在运行时生成一个 24×24 的实心圆点图标（橙色），干净替代默认占位图

### 2.4 输出数据结构：`TaggedGeometry`
文件：[Components/TaggedGeometry.cs](gh-plugin/CarbonTools/Components/TaggedGeometry.cs)

- 纯数据类：`{ IGH_GeometricGoo Geometry, Color Color }`
- 用 Grasshopper 内置的 `GH_ObjectWrapper` 包一层往外传，**没有自己实现一套 `IGH_Goo`**（会牵扯 `CastFrom/CastTo/Write/Read` 等一堆样板代码，`GH_ObjectWrapper` 本身就是 GH 为"任意 .NET 对象走通用参数"准备的官方壳）
- 这是这次架构上比较关键的一步：之前颜色只存在 CC Group 组件内部（`CurrentColor` 字段），**不随线传递**；现在颜色跟着每个几何对象一起打包传给下游，CC Sync 才有可能知道每个物体该归到哪个颜色组

### 2.5 视口预览染色
- 重写 `DrawViewportWires` / `DrawViewportMeshes`（覆盖默认实现，不再用 GH 默认绿色/选中色预览）
- 遍历输出参数的 `VolatileData.AllData(true)`，解包出 `TaggedGeometry`，用 `tagged.Color` 构造 `GH_PreviewWireArgs` / `DisplayMaterial` 分别画线框和网格
- 效果：Rhino 视口里的显示颜色 = 用户在色块上选的颜色，不是 GH 默认配色

## 三、CC Sync 电池

文件：[Components/CCSyncComponent.cs](gh-plugin/CarbonTools/Components/CCSyncComponent.cs)

### 3.1 电池形态（对应决策文档第十四节的草图）
- 输入：
  - `Objects`（generic, list）—— 接一个或多个 CC Group 的 `Tagged Objects`。GH 原生支持多根线接到同一个输入口自动合并成一个列表，所以暂时**没有**做手动"+"加口（`IGH_VariableParameterComponent`），先够用
  - `Run`（Boolean）—— 持续同步开关：为 true 时启动本地服务器并且每次重算都刷新数据；为 false 关闭服务器
  - `Open`（Boolean）—— 按钮语义，做了**上升沿检测**（`_previousOpen` 字段），只在 false→true 的瞬间弹一次浏览器，避免拖滑块时开出一堆标签页（这是决策文档里特别强调的一点：Sync 开关必须拆成两个,原因就是这个）
- 输出：
  - `Status`（文本）：当前状态描述，例如 `Running on http://localhost:53665/ - 12 objects across 3 groups`
  - `Port`（整数）：本地服务器端口，未运行时为 `-1`
- `RemovedFromDocument` 里会把服务器关掉，避免电池被删除后线程/端口还挂着

### 3.2 同步协议 JSON（对应决策文档第十五节）
文件：[Sync/SyncJsonBuilder.cs](gh-plugin/CarbonTools/Sync/SyncJsonBuilder.cs)

```json
{
  "meta": {
    "units": "m",
    "origin_offset": [x, y, z],
    "timestamp": "2026-08-26T12:00:00Z",
    "mesh_tolerance": 0.01
  },
  "groups": [
    { "color": "#E67E22", "objects": [ { "id": "...", "quantity": {...}, "mesh": {...} } ] }
  ]
}
```

- 按 `TaggedGeometry.Color` 分组（转成 `#RRGGBB` 十六进制）
- **单位换算到米**：读 `RhinoDoc.ActiveDoc.ModelUnitSystem`，用 `RhinoMath.UnitScale(...)` 算比例，所有长度/面积/体积/网格坐标都乘这个比例，网页端不需要关心 Rhino 文档用的是毫米还是英尺
- **origin_offset 归零**：算所有传入几何的联合包围盒，取 `Min` 点作为偏移量，网格坐标减去这个偏移——避免真实地理坐标（动辄几十万）传到 three.js 后 float32 精度不够抖动/撕裂（决策文档第十五节明确提到的坑）
- **mesh_tolerance**：读 `RhinoDoc.ActiveDoc.ModelAbsoluteTolerance`

### 3.3 单个物体的数量与网格
文件：[Sync/GeometryQuantities.cs](gh-plugin/CarbonTools/Sync/GeometryQuantities.cs)、[Sync/MeshExport.cs](gh-plugin/CarbonTools/Sync/MeshExport.cs)

- `Point` → `count = 1`
- `Curve` → `length`（`GetLength()`）
- `Brep` / `Mesh` → `area`（`AreaMassProperties`），闭合的话再算 `volume`（`VolumeMassProperties`）
- `Surface` / `Extrusion` → 转 `Brep` 复用上面逻辑（**踩了一个坑**：`Extrusion` 在 RhinoCommon 里派生自 `Surface`，`switch` 里 `case Surface` 写在 `case Extrusion` 前面会导致后者的分支编译器判定"不可达"，报 `CS8120`，调整了两处 `switch` 分支顺序才过编译）
- **几何 id**：不是逐顶点精确哈希，是一个"形状特征代理"——把类型名 + 包围盒 + （网格的顶点/面数 或 曲线长度）拼成字符串，MD5 后取前 16 位。够用来做增量更新的候选方案，但不是唯一性严格保证，标注为已知简化
- **mesh 导出**：`Brep`/`Surface`/`Extrusion` 用 `Mesh.CreateFromBrep(..., MeshingParameters.Default)` 网格化后 `Append` 合并；`Mesh` 直接用；坐标按 `unitScale` 缩放再减 `origin_offset`；面数组按三角形/四边形原样出 `[a,b,c]` 或 `[a,b,c,d]`

### 3.4 内嵌本地服务器
文件：[Sync/CarbonSyncServer.cs](gh-plugin/CarbonTools/Sync/CarbonSyncServer.cs)

对应决策文档第十六节"自研 GH 组件内嵌本地服务，不用 Speckle"：

- 用 `System.Net.HttpListener`，绑定 `http://localhost:{port}/`（用 `localhost` 而非通配符，Windows 下不需要管理员权限/URL ACL）
- **自动找空闲端口**：先起一个 `TcpListener(IPAddress.Loopback, 0)` 让操作系统分配端口，读出端口号后立刻停掉，再拿这个端口号给 `HttpListener` 用
- 后台 `Thread`（`IsBackground = true`）里跑阻塞式 `listener.GetContext()` 循环处理请求，不用回调，逻辑简单不容易出竞态问题
- 路由：
  - `GET /data.json` → 当前同步的 JSON（`UpdateData()` 由 CC Sync 每次 `SolveInstance` 调用刷新）
  - `GET /`（其他所有路径）→ 三维预览页面（见下一节），作为**嵌入资源**打包进 `.gha`，不依赖外部文件路径，插件本身完全自包含

## 四、网页端三维骨架（three.js）

文件：[WebAssets/viewer.html](gh-plugin/CarbonTools/WebAssets/viewer.html)

对应决策文档第十六节"推进顺序"里的第 3 步（"网页骨架：three.js 读 JSON，做三维显示 + 按颜色着色 + 侧栏列表"）。讨论过程中用户一度提议直接上 WebSocket，按文档"别一上来就啃 WebSocket"的提醒说服先做这一步，验证完整链路（GH → 本地服务 → 网页三维）之后再考虑换传输层。

### 4.1 技术选型
- three.js r128（CDN，`cdn.jsdelivr.net`）+ 配套的 `OrbitControls.js` 非模块化版本，避免 ES Module 版本在这个场景下的额外复杂度
- 打包方式：整个 `viewer.html` 作为 `<EmbeddedResource>` 编进 `CarbonTools.csproj`，`CarbonSyncServer` 用 `Assembly.GetManifestResourceStream("CarbonTools.WebAssets.viewer.html")` 读出来直接当字符串返回

### 4.2 坐标系转换（决策文档第十五节第 5 条）
Rhino 是 Z-up 右手系，three.js 是 Y-up 右手系。转换用的是：

```js
threeX = rhinoX
threeY = rhinoZ
threeZ = -rhinoY
```

这个写法在换轴的同时**保住了右手系手性**（否则单纯交换 Y/Z 会把右手系变成左手系，导致三角形环绕方向翻转、背面朝向渲染出问题）。

### 4.3 页面结构
- 左侧视口：`PerspectiveCamera` + `WebGLRenderer` + `OrbitControls`，环境光 + 方向光，`GridHelper` 铺地
- 右侧栏：顶部显示"N objects, M groups"汇总；每个颜色组一行（色块 + 十六进制颜色 + 物体数 + 显示/隐藏勾选框）
- 网格重建：`obj.mesh.faces` 里三角形直接用，四边形拆成两个三角形（`[a,b,c]` + `[a,c,d]`），用 `THREE.BufferGeometry` + `Float32BufferAttribute` 建几何，材质按组颜色统一赋色（`MeshStandardMaterial`）
- **轮询刷新**：每 1.5 秒 `fetch('/data.json', {cache:'no-store'})` 重新拉取并重建整个场景（目前是暴力全量重建，不是增量更新）——这是"先用 HTTP/轮询把链路跑通，以后再换 WebSocket"这个决策下的过渡方案
- 首次加载完成后自动把相机对准整个场景的包围盒（`Box3.setFromObject` + 简单的距离/位置计算）

### 4.4 验证方式
没有打开真实 Rhino，而是把编译出的 `.gha` 复制成 `.dll` 后缀，用 PowerShell `Add-Type` 直接加载 `CarbonSyncServer` 类（这个类不依赖 RhinoCommon/Grasshopper 的具体类型，可以脱离 Rhino 环境单独跑），灌入两组手写的示例 JSON（一个矩形面 + 一个立方体），启动服务器后：
- `curl`（`Invoke-WebRequest`）验证 `/data.json` 和 `/` 都返回 200
- 用 Claude Code 自带的 Browser 工具打开页面，读取 `get_page_text` 和 `read_console_messages`，确认：
  - 侧栏正确显示 "2 objects, 2 groups"
  - 两个颜色分组（`#E67E22`、`#3498DB`）都正确列出
  - 控制台没有报错（three.js / OrbitControls 加载、`fetch`、场景构建都没有异常）

## 五、已知简化 / 留给后面的坑

- **Objects 输入口没做"+"手动加口**（`IGH_VariableParameterComponent`），目前靠 GH 原生的多线合并，够用但不如文档草图里画的那么明确
- **几何 id 是形状特征代理，不是严格的内容哈希**，目前也没有利用它做真正的增量更新（每次都是全量重建 JSON、网页端每次也是全量重建 three.js 场景）
- **网页端是轮询 `/data.json`（1.5 秒一次），不是实时推送**——这是本次会话最后讨论到、但还没动手的下一步：把传输层换成 WebSocket（决策文档说得很清楚，协议不变，只是网页端换掉拉数据的那一个函数，GH 端也要把"响应 HTTP 请求"换成"主动推送"）
- **Curve / Point 目前在三维视图里不显示**（协议里它们的 `mesh` 字段是 `null`，只有 `length`/`count` 数值），viewer.html 目前只画有 mesh 的物体，线要不要在网页上画出来还没做决定
- **`_statusLine` 字段目前存了没用上**（`CarbonSyncServer` 里预留的，`/` 页面还没有用它显示服务器端状态文字，只是占位）
